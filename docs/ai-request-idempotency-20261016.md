## 适用范围

## 行为

1. 发送前固定 API 来源、账号、家庭、患者档案、额度来源、操作和请求输入。共享日志只保存摘要、请求 ID、状态和时间，不保存原文、模型响应或令牌；写入及读回失败则不发送。
2. 句子生成按完整提交内容派生稳定 `cai_` ID。分词按原始文本派生 ID，并另存完整请求体指纹；后台同步词表、确认补图或修改缺词清单不能悄悄产生新付费请求。重复词、否定、标点和顺序不被标准化抹除。
3. 超时、断连、重开端口或页面、重复点击、并发点击和完成后的重复点击保持原 ID。**没有自动过期换 ID，也没有“强制再次付费生成”入口。** 同样输入会重放已有结果；改变原始输入才构成另一请求。
4. 原句相同但辅助上下文变化时，本机返回 `AI_REQUEST_INPUT_CHANGED`，提示保留本地分词并核对原请求。若元数据丢失或另一标签页上下文不同，仍产生同一 ID，服务端完整请求指纹返回 `USAGE_ID_REUSED`，不调用模型或另计费。本批不保存原始请求正文，因此暂不能自动还原变更前的词表以恢复结果。
5. 发送前及返回后检查账号、令牌、档案、额度和实际 API 目标；期间切换后不展示旧结果。旧请求的 401 仅当其 Authorization 仍属于当前会话时触发退出。
6. 服务端先重新授权并原子预留，再执行供应商。结果及结算在同一加密 CAS 中完成后才发送 HTTP JSON。进程重建或客户端中途断开后，重试读取已有结果，不再进入供应商控制器。两类 SDK 请求均禁止隐式重试。
7. 执行/用量未知保留预留并返回待核对状态；持久化失败也不再次调用供应商。不能把缺失 usage 当作证明没有执行。已有对账流程继续负责核对未知消费。

## 业务码和保留规则

| 情况 | 行为 |
|---|---|
| 已完成且结果可用 | 返回原状态和有限 JSON，`X-Care-Idempotency-Replayed: true` |
| 仍执行或无法确认结果 | `AI_REQUEST_PENDING_RECONCILIATION`；保留预留，不调用第二次 |
| 结果/结算写入失败 | `AI_RESPONSE_PERSISTENCE_UNAVAILABLE`；保留同一请求 ID |
| 已完成但旧记录没有结果/结果过期 | `AI_REQUEST_ALREADY_COMPLETED`；不自动重新付费 |
| 同 ID 请求体或计价指纹不一致 | `USAGE_ID_REUSED`；拒绝重用，不换 ID 重发 |
| 本机无法保存身份 | `AI_REQUEST_STORAGE_UNAVAILABLE`；发送前停止 |
| 原句相同而辅助上下文变化 | `AI_REQUEST_INPUT_CHANGED`；发送前停止 |
| 请求期间身份/档案/额度变化 | `AI_REQUEST_CONTEXT_CHANGED`；拒绝发送或丢弃旧结果 |
| 客户端带 Care 身份但服务端未启用 Care | `CARE_TRIAL_CONFIGURATION_INVALID`；不降级旧计费 |

结果只保存公开接口字段，错误只保存稳定业务码和通用说明，不保存供应商原始错误或 headers。结果上限 64KiB，可重放 24 小时；过期正文在下一次账本修改时惰性清理，财务凭据继续保留。**没有新增定时删除任务，24 小时不是物理清除的精确时限。**

新 `cai_` ID 在服务端使用递归排序的 JSON 指纹，数组顺序不变，消除 JSON 键序导致的误冲突。旧 ID 继续原算法，保持旧账本兼容。

| 变动 | 意图 | 决策 | 理由 | 证据 | 生效范围 |

| 测试与候选构建 | 核验实际接线 | 复用既有 Swagger/SDK、组件和浏览器测试 | helper 通过不能证明真实调用路径正确 | 详见本轮证据目录 | 合成数据与本机构建，非上线验收 |
