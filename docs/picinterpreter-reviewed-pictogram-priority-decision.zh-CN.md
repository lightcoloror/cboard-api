# 复用原图语家人工审核图符作为 CBoard 在线补图优先候选

- 决策状态：已生效（工程级）
- 记录时间：2026-07-22 22:28:21
- 最后更新：2026-07-22 23:58:01
- 执行工具 / 模型：Codex（GPT-5）
- 相关工程：原 PicInterpreter、`cboard-api`、CBoard Web、图语家微信小程序

## 意图

改善“文字和分词正确，但在线通用搜索把不合适图片排在前面”的核心问题。直接复用原图语家已经逐场景人工核验的概念与 ARASAAC ID，不重新训练模型、不复制旧 React 页面，也不把图片二进制加入 CBoard 或微信代码包。

## 决策

1. 从原图语家 `data/pictogram-eval-results.json` 的 41 个已审核场景中，确定性提取 138 个“概念 → ARASAAC ID”关系，保存为紧凑 schema v1；记录原文件更新时间和 SHA-256，便于追溯。
2. 继续复用 cboard-api 已有 ARASAAC `bestsearch -> search`、OpenSymbols 回退、同源图片代理、许可元数据、缓存、4 候选上限和照护者确认，不新增依赖、路由或客户端协议。
3. 中文 token 有审核 ID 时，审核候选排在实时 `bestsearch` 结果之前并稳定去重；首轮上游为空或失败时直接返回审核候选，不再执行宽泛查询。无审核 ID 的词完全保持原搜索顺序。
4. 审核候选仍只进入“照护者选择并确认”流程，不自动覆盖默认板、个人图卡、分词结果或历史。图片仍由现有 cboard-api ARASAAC 代理按需获取。
5. “受伤了”等原词典中会改变医疗语义的宽泛别名不进入审核索引；原文继续保留并交给照护者处理。
6. 首轮对当前 CBoard 分词会产生、且能由原 41 个场景逐项证明语义等价的 14 个窄别名，先解析到原审核概念再取 ID：一点 → 少许、然后 → 以后、慢慢 → 慢的、穿 → 穿衣服、累 → 累的、按 → 按下、按钮 → 按钮开关、干净 → 干净的、烫 → 烫的、平静 → 平静的、走 → 走路、包扎 → 包扎伤口、晴朗 → 晴朗的、出门 → 出去。抬、叫、体温、呼吸困难、按铃、受伤了等有歧义或会改变医疗含义的单词查图仍保持未映射。
7. 41 场景真实重放再补 13 条句级审核桥接：一会儿、九点、三点、声音大、天气晴朗、有人叫门保留自然分词并解析到单个审核概念；拿给、呼吸困难、抬手、走一点路、出门前、有事告诉我、听安静的音乐按原人工 sequence 改写为多个审核概念。呼吸困难本身仍不在 API 单图别名中，只在完整短语分词阶段变成“呼吸 / 困难的”。

8. 继续逐句复核原 41 场景后，只增加 1 条一对一别名“平静地 → 平静的”和 11 条有原人工 sequence 直接证据的短语改写：杯子里的水、第一步、冰箱里的鸡汤还有一点、太阳出来、用毛巾擦干、换干净的尿布、用勺子、用手机打电话、吃药时间到了、用纸巾遮住嘴、地面有水。来看看你、叫护士、不要滑倒、按铃、捂嘴和屋里闷等存在跨场景冲突、否定风险或原评测明确缺图的内容继续不映射。
9. 第三轮只加入 4 条上下文完整、可由原人工 sequence 逐项证明的改写：医生下午三点来看你 → 医生 / 下午 / 三点整 / 来 / 你；我叫护士 → 我 / 说 / 护士；坐轮椅下楼散步 → 轮椅 / 电梯 / 下 / 散步；或者抬肘咳嗽 → 抬肘咳嗽。通用“来看你、叫护士、下楼”继续保持原分词；“先喝水”泛化因会让“先喝水再吃药”丢失顺序词而被全量安全回归拒绝并撤回。

## 理由

- 原图语家已经为这些概念做过逐图核验，复用 ID 比重新依赖通用搜索排名更符合“尽量复用、不要自行研发”的原则。
- CBoard 默认板面向通用 AAC，不可能离线覆盖所有照护场景。对原 41 条评测文本实测，138 个唯一概念中默认板直接命中 47 个，概念覆盖率为 34.06%；缺口应由现有在线补图链补齐，而不是把 295 张远程图全部塞入微信包。
- 服务端数据索引不会增加微信主包体，也不会把 GPL React DOM、Material UI 或原 Next.js 运行时搬进小程序。
- 保留实时候选和人工确认，既能利用上游更新，又能防止审核索引或通用搜索结果未经复核直接改变患者表达。
- 别名不是凭语言模型猜测生成，而是把原评测概念与当前 CBoard 对同一 finalText 的实际分词逐场景对照后得到；只纳入能证明一对一等价的窄映射，减少“分词变化导致审核数据无法命中”，不扩大自动推断边界。

## 证据

- 词典差异审计：原图语家 96 个主词在当前 CBoard 中性词典中 0 遗漏；当前词典扩展为 108 个。仅“有痰 → 咳嗽”和“受伤了 → 出血”未照搬，后者已有安全回归明确禁止。
- 原评测覆盖审计：41 个场景、138 个唯一概念；CBoard 默认板直接匹配 47 个（34.06%），且没有 `partial` 错配。
- 索引完整性：schema v1、41 cases、138 concepts、每概念 1–4 个正整数 ID；源文件 SHA-256 为 `E37C92F3E198DBBFBD03DDFBCE800883529B3BFC704A2D143FE28C774FAF5D9A`。
- cboard-api 图符聚焦回归：`21 passing`；全部无数据库单元回归：`307 passing`。
- CBoard Web 缺词/运行图符/照护确认：`3 suites / 14 tests`；微信在线候选/回退/表达补图：`4 files / 15 tests`。
- 真实 ARASAAC 只读验证：`水` 的审核 ID `2248` 和 `测体温` 的审核 ID `36852` 均排第一；两次 `bestsearch` HTTP 200，对应 PNG 下载 HTTP 200，分别为 9,217 B 和 18,671 B。

- 41 个原场景通过当前 CBoard 默认板、真实分词与 matcher 重放后，共产生 211 次、123 个唯一未匹配 token。仅概念原文可命中审核索引 121/211（57.35%）；加入 14 个窄别名后为 146/211（69.19%）、70 个唯一 token，净增 25 次和 14 个唯一词。
- 别名完整性回归逐项确认所有目标概念存在、解析结果与原审核 ID 完全一致。真实 ARASAAC 追加抽样：然后 → 13080、一点 → 7209、慢慢 → 4676 均排第一，对应 PNG 分别下载 6,088 B、6,509 B、5,038 B。

- 第二轮句级复核后，审核候选覆盖由 164/198（82.83%）提升到 165/185（89.19%），唯一审核 token 从 88 增至 89；剩余未审核缩减到 20 次 / 16 个唯一词，并由重放测试显式锁定。
- API 与 CBoard 两份 schema v1 索引保持 41 cases / 138 concepts / 21 aliases，规范化 SHA-256 同为 `473D20B8BAA3DB9E8CA1F46F72D78C1C17E964700D3F57382147D63B112AEA58`。
- CBoard 聚焦 5 suites / 234 tests、全量 194 suites / 1308 tests / 72 snapshots 和 production build 通过；API 图符聚焦 18 passing、无数据库单元全量 307 passing；微信 65 files / 294 tests、TypeScript、ESLint、186 app / 29 core 边界、production build 和质量门 7/7 通过。
- 微信构建包体：main 1,249,564 B、caregiver 570,813 B、emergency 94,003 B、management 509,781 B、backup 598,739 B、ocr 64,693 B，全部低于 1.5 MiB 建议线；插件下载大小仍需上传前用官方性能扫描验证。
- 第三轮上下文改写后，审核覆盖由 165/185（89.19%）提升至 167/183（91.26%），唯一审核 token 由 89 增至 90；剩余 16 次 / 12 个唯一词。第一次聚焦回归阻止“叫护士、来看你、下楼”扩散到其他句子，第一次全量回归又阻止“先喝水”删除服药顺序，最终保留 4 条严格上下文规则。
- 最终 CBoard 聚焦 5 suites / 242 tests、全量 194 suites / 1316 tests / 72 snapshots 与 production build 通过；微信 65 files / 294 tests、TypeScript、ESLint、186 app / 29 core 边界、production build 和 7/7 质量门通过。微信 main 1,249,564 B、caregiver 571,172 B、emergency 94,003 B、management 510,140 B、backup 599,098 B、ocr 64,693 B。

## 生效范围

- 生效：cboard-api 中文在线补图候选排序及上游首轮失败时的已审核候选回退；Web 与微信通过既有响应协议自动受益。
- 不变：分词、matcher、本地默认板、个人图片、纠错记忆、接收历史、来源许可展示、照护者确认和图片缓存协议。
- 安全边界：别名只改变“已审核候选 ID 的查找键”，不改用户可编辑原文和分词，不把别名词写回患者表达，也不让候选绕过照护者确认。
- 不包含：公共图库投稿、自动发布、AI 生图、完整离线扩图库、真实生产部署或未经人工确认的自动换图。
- 公共投稿边界：继续服从 `public-pictogram-contribution-reuse-review.md`；私有家庭照片不得进入公共图库，只有成熟上游投稿/审核 API 或明确批准独立 moderation 运营责任后才另行实现。
- 操作边界：未部署、预览、上传、发布、提交或推送；没有打开、激活、聚焦、抬升或置顶微信开发者工具或任何应用窗口。
