## 状态与入口

已增加独立设备会话、家庭与患者档案、按档案授权、一次性邀请、加密共享图库、离线同步、冲突处理、修改记录和旧图库复制入口。Web 设置进入 `/care`；小程序照护设置进入患者档案与家庭协作。原有访客沟通、账号设置和密码加密整包备份保持独立。

这是候选工程实现，默认关闭患者协作；未替换正式云端 API、未迁移线上真实资料、未公开发布。真实微信设备及正式域名网络验收另行记录，构建成功不替代真机验证。

## 配置与部署前检查

后端：

- `CARE_COLLABORATION_ENABLED=true`：开启 `/care`。关闭时返回 503 `CARE_DISABLED`。
- `CARE_ENCRYPTION_KEYS`：JSON 对象，键为密钥版本标识，值为 32 字节密钥的 64 位十六进制表示。只放受限环境配置，不入 Git、日志或客户端。
- `CARE_ENCRYPTION_ACTIVE_KEY`：当前写入使用的版本标识。轮换时保留旧版本，直到其数据完成重加密并验证恢复；删除旧密钥会导致旧数据不可读。
- `CARE_MEDIA_ROOT`：可选、专用绝对目录，保存认证加密后的媒体。目录需持久化及备份；不得指向已有业务目录或临时容器文件系统。
- 未指定 `CARE_MEDIA_ROOT` 时复用现有 Azure Blob 适配接口；`CARE_MEDIA_CONTAINER` 默认 `cboard-care-private`，需要独立私有容器和相应存储配置。候选隔离验收使用文件适配器，未核验真实 Azure 配置。

Web 构建：`REACT_APP_CARE_COLLABORATION=true`。小程序构建：`TARO_APP_CARE_COLLABORATION=true`，同时沿用现有云功能开关和 API 基址。所有公网及微信合法域名仍遵循备案和发布准备流程。

认证会话变更不受患者协作开关控制：每次登录产生独立会话及有期限的 JWT，最长 30 日；无 `sid` 的旧令牌要求重新登录。上线前必须部署兼容 401 的两端客户端并通知试用者。密码变更继续沿用 `authVersion` 撤销机制。

## 数据与接口

- `CareFamily` 记录服务空间、创建者及订阅关联预留。`CareProfile` 以单文档版本比较更新，把授权变更、业务资源、操作回执及审计置于同一原子边界，不依赖单节点 Mongo 不具备的跨文档事务。
- `Communicator` 保存不含患者姓名的关联标记；旧查询过滤这些标记，患者业务内容只能从 `/care` 经授权读取。付款人不自动得到访问权限。
- 姓名、资源、邀请凭据和修改记录保存在 AES-256-GCM 加密数据中，绑定档案上下文；媒体绑定档案与媒体 ID。账号／家庭／成员索引属于访问控制元数据，不宣称服务方无法解密。
- `/user/sessions`：列出及撤销自己的设备；`/user/logout` 撤销当前会话。断网退出只能确认本机清除，界面明确说明未确认云端撤销。
- `/care/families`、`/care/profiles`：创建和列举；`/care/profiles/{profileId}` 返回快照或 `since` 增量，同时返回当前权限。
- `/care/profiles/{profileId}/commands`：`put/delete`、`invite/revokeInvite/grant`。写操作必须携带唯一 `operationId`；资源附 `kind/resourceId/baseVersion/value`。重复操作校验请求指纹；不同内容复用同一 ID 返回 409。
- `/care/invitations/accept`：接受 72 小时一次性邀请。凭据只通过请求体传递；生成凭据后由用户自行决定分享对象。
- `/care/profiles/{profileId}/media`：上传；`.../media/{mediaId}`：鉴权读取／删除。上传校验大小、文件签名及 SHA-256，文件落盘后再登记；删除先标记不可访问再删除密文，失败可重试。
- `/care/profiles/{profileId}/audit`：授权范围内操作记录，不包含病情原文或图片内容。
- `/care/migration-preview`：按当前账号读取旧资料引用，不推定归属、不执行迁移。

首期媒体接口支持 PNG、JPEG、WebP，单图最大 4 MiB；档案加密前结构数据最多 5 MiB，超限拒绝写入而不截断历史。录音、视频共享及更大档案的分区存储需要后续扩展，现有本地功能保持可用。

## 离线与迁移

同一同步核心用于两个客户端。Web 用 IndexedDB 事务，小程序用专用文件原子替换；缓存、待上传队列及冲突按账号／家庭／患者分区。前台每 30 秒、回到前台及网络恢复时同步。编辑先持久化，再尝试上传；断网保留队列。服务端拒绝的非法内容暂停该项，不无期限自动重试。

同资源版本冲突保留双方内容；采用本机版本使用新操作 ID 和最新基础版本。云端已删除时禁止恢复同一个 ID。权限撤销后锁定缓存入口及待上传内容，不能承诺离线设备即时清除。

旧资料复制复用 `library.json` ZIP 格式。用户选择明确目标患者、查看数量并确认后，图库作为新增资源进入队列；来源映射和备份指纹保存在该账号／档案的本地迁移记录中，同一备份重复导入跳过已排队或已有资源。旧数据、原始备份及旧接口不修改。加密备份先通过原有密码恢复流程处理，不向协作服务器提供恢复密码。首期不迁移完整设备设置、语音密钥、沟通历史、录音或视频。

## 验收与恢复

测试必须经工作区受管测试入口运行。后端单元测试包含 `careCollaboration.unit.js` 和 `deviceSessions.unit.js`；Web 定向测试覆盖共享界面、图库迁移及原图库备份回归。小程序运行 `tsc --noEmit` 与正式编译。

`test/integration/careHttp.mongo.integration.js` 只接受显式 `care_test_<随机值>` 数据库。它使用真实 HTTP、Mongo、独立会话与加密文件适配器，验证读写、并发回执、邀请、撤权、图片恢复及会话退出；不导入 `db.js` 或正式用户。测试结束按精确数据库名与临时路径清理。

正式备份必须同时包含 Mongo 数据及媒体密文，密钥另行受限备份。隔离演练验证的是合成数据恢复，不能作为正式备份已经配置或真实资料可恢复的证明。

回滚先关闭客户端及服务端患者协作开关，保留共享集合、密文及密钥；不要回滚到接受旧无会话令牌的认证代码。原有个人／访客数据不因关闭协作功能删除。
